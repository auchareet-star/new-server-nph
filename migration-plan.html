HAOS Migration — แผนการดำเนินงาน

ย้ายฐานข้อมูล + แอปพลิเคชัน OLD → NEW (DB master + reuse replica เดิม) · ระบบโรงพยาบาล 24×7
Execution 7 วัน (Day 1–7) 🌙 ปิดระบบ 1 คืน (Day 6) IT เตรียม: NAS + mount
สรุปสำหรับผู้บริหาร: งานเตรียมทั้งหมด (seed ข้อมูล, scripts, ทดสอบ, เตรียม cutover) ทำระหว่างวันโดยระบบไม่หยุดบริการ · ใช้เครื่อง replica เดิม (ไม่ต้องลงเครื่องใหม่) · ระบบหลัก (HIS) หยุดจริงเพียงคืน Day 6 คืนเดียว · ระบบค้นหา (ELK) ทำงานต่อเนื่องระหว่าง cutover (ใช้ index เดิม) เหลือเพียงช่วง re-index ใหม่ ≤10 นาทีตอนท้าย · ระยะเวลายืนยันจาก dry-run (Day 3) · เริ่มนับ 7 วันเมื่อ Day 0 (NAS + access) พร้อม.
DAY 0เตรียมความพร้อม (Prerequisite)☀️ กลางวัน
  • จัดหา NAS ~1TB + mount เป็น share ให้ครบ 3 เครื่อง (main-old, app VM ใหม่, db VM ใหม่)IT
  • เปิดให้ Ayodia เชื่อม SQL ของ main-old (ใช้ account db_owner ที่มีอยู่)IT
  • อนุมัติ + นัด maintenance window สำหรับคืน Day 6IT
DAY 1สำรวจ + Seed ข้อมูลตั้งต้น⚡ online (off-peak)
  • สำรวจ recovery model / ขอบเขตข้อมูล / โฟลเดอร์แอป + ทดสอบเขียน-อ่าน shareAyodia
  • Full backup ฐานข้อมูล (~2TB) ขณะระบบทำงาน แล้วขนผ่าน drive ไปเครื่องใหม่ — รันช่วงนอกเวลาเร่งด่วนAyodia
DAY 2สร้างระบบ Sync ข้อมูล☀️ กลางวัน
  • เขียน script sync ไฟล์แอป + script สำรอง transaction log ขึ้น shareAyodia
  • เริ่มส่ง log ต่อเนื่องเข้าเครื่องใหม่ (ระบบเก่ายังทำงานปกติ)Ayodia
⚙️ script ตั้งเป็น Scheduled Task + เขียน log ลง share → ทำงานต่อเนื่องเองแม้ remote หลุด (ไม่ต้องเฝ้าจอ)
DAY 3ทดสอบเสมือนจริง (Dry-run)☀️ กลางวัน
  • วัดเวลาจริง: cutover ฐานหลัก + rebuild replica + ELK re-index (~10 นาที) → ได้ระยะ downtime ที่แท้จริงAyodia
  • ทดสอบ rebuild replica จากฐานใหม่ + ทดสอบ clear/re-index ELK จาก replicaAyodia
  • ตรวจสอบความถูกต้อง: FILESTREAM / สิทธิ์ผู้ใช้ / เว็บแอป (บนเครื่องใหม่ที่แยกวง)Ayodia
DAY 4เตรียมแผน Cutover☀️ กลางวัน
  • จัดทำ cutover runbook + rollback plan (แผนถอยกลับหากไม่สำเร็จ)Ayodia
  • ปรับ security เครื่องใหม่ + activate license + ตั้งนโยบาย backup ใหม่Ayodia
DAY 5ซ้อม UAT + เผื่อแก้ปัญหา☀️ กลางวัน
  • ซ้อมขั้นตอน cutover + แก้ไขปัญหาที่พบ + เคาะเกณฑ์ go / no-goAyodiaIT
DAY 6CUTOVER — สลับระบบ🌙 ปิดระบบหลัก (HIS)
  • ฐานข้อมูลหลัก: หยุดแอป → ส่ง log ก้อนสุดท้าย → เปิดใช้ฐานข้อมูลเครื่องใหม่ → สลับ network → ตรวจสอบ → เปิดบริการ HISAyodiaIT
  • Replica: กู้สิทธิ์เข้า replica (restart ฐานข้อมูล) → สร้างใหม่จากฐานหลักเครื่องใหม่ (ช่วงนี้ ELK ยังค้นหาได้ด้วย index เดิม)Ayodia
  • ค้นหา (ELK): clear + re-index จาก replica (~10 นาที) → ค้นหาได้ข้อมูลสดAyodia
⏱️ HIS หยุดสั้น (ตามผลวัด Day 3) · ระบบค้นหา (ELK) ทำงานต่อเนื่องบน index เดิม เหลือเพียง ≤10 นาทีช่วง re-index · รวมทุกอย่างไว้คืนเดียว ไม่ปิดระบบซ้ำ
DAY 7ตรวจรับ + ส่งมอบ☀️ กลางวัน
  • ตรวจสอบระบบใหม่ + UAT sign-off + เฝ้าระวัง (ระบบ live บนเครื่องใหม่แล้ว)AyodiaIT
  • ปลดระวางเครื่อง DB เก่าหลังระบบเสถียรIT
