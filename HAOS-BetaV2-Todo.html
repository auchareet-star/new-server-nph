Server: Lenovo ThinkSystem SR650 V4 Target: ESXi 8 + 4 VMs Design: Pool 1 Master Data | Pool 2 Master Log | Pool 3 Shared
0
สิ่งที่ต้องตัดสินใจก่อน (Pre-Decisions) — ต้องได้คำตอบก่อนเริ่ม implement
⚠️ ถ้าตัดสินใจเหล่านี้ไม่เสร็จ การ implement อาจต้อง redo ทีหลัง
  • ยืนยัน Backplane type กับ Lenovo (AnyBay ต้องเป็น AnyBay)
    ขอ Config ID / DCSC sheet + cabling diagram — ถ้าไม่ใช่ AnyBay ต้อง redesign ทั้งหมด เพราะ 940-16i คุม NVMe ไม่ได้ถ้าเป็น direct-attach
    PM IT Manager
  • ยืนยัน DB growth rate เฉลี่ยต่อปี กับ DBA
    ถ้า ≤10%/ปี → β-v2 รองรับได้ 3 ปี (Master pool 6.4TB) | ถ้า >10%/ปี → ต้องขอเพิ่ม NVMe drive 2 ลูก
    DBA
  • ยืนยัน Replica role — passive DR หรือ readable secondary?
    passive DR = ใช้ license ที่มีอยู่ได้ | readable secondary = ต้องซื้อ SQL Enterprise เพิ่มอีก 1 ตัว (~฿490K)
    DBA ผู้บริหาร
  • ตัดสินใจเก็บ bare metal เดิมเป็น DR standby หรือปลด
    เก็บ = มี fallback ถ้า server ใหม่มีปัญหา (แนะนำอย่างน้อย 3-6 เดือน) | ปลด = ไม่มี failover แต่ประหยัด license + maintenance
    ผู้บริหาร
  • ยืนยัน Downtime window สำหรับ cutover — ยอมรับกี่ชั่วโมง?
    กระทบ migration strategy: live sync (downtime สั้น) vs cold copy (downtime นาน) และ rollback window
    ผู้บริหาร IT Manager
  • วางแผน Backup + DR strategy (ไม่อยู่ใน BOM)
    server ใหม่ยังไม่มี plan backup off-site — ต้องจัดทำก่อน go-live
    IT Manager DBA

RAID Configuration (ผ่าน 940-16i Controller)
🔴 ห้าม improvise — ต้องตรง spec นี้เท่านั้น ถ้าต้องเปลี่ยนต้องขออนุมัติ PM ก่อน

Boot Array

  • Boot SATA #1 + SATA #2 → RAID 1 → 480 GB usable
    target สำหรับ ESXi install
    Engineer

NVMe Data Pools

  • Pool 1 NVMe #1-4 → RAID 10 → 6.4 TB usable (DS-MASTER-DATA)
    Stripe size 64KB — สำหรับ Master OS + SQL Data (.mdf) + TempDB
    Engineer
  • Pool 2 NVMe #5-6 → RAID 1 → 3.2 TB usable (DS-MASTER-LOG)
    Stripe size 64KB — สำหรับ SQL Log (.ldf) โดยเฉพาะ — นี่คือ key advantage ของ β-v2
    Engineer
  • Pool 3 NVMe #7-8 → RAID 1 → 3.2 TB usable (DS-SHARED)
    Stripe size 64KB — สำหรับ Replica+ELK, App, Report (low-I/O workloads)
    Engineer

3
Post-Install Validation — ต้องผ่านทุกข้อก่อน Go-Live
  • Run IOmeter / CrystalDiskMark บน Master VM
    Target: >200K IOPS random read/write (NVMe RAID 10 ควรทำได้สบาย)
    Engineer DBA
  • Run SQLIOSim บน Master VM
    ต้อง: ไม่มี error + latency <5ms
    DBA
  • Verify SQL buffer pool โตถึง ~200 GB หลัง warmup
    ใช้ SELECT physical_memory_in_use_kb FROM sys.dm_os_process_memory
    DBA
  • Verify Log write latency <1ms ตอน idle
    ดูจาก sys.dm_io_virtual_file_stats หรือ Windows Performance Monitor
    DBA
  • ทดสอบ Backup + Restore (full + log backup) ให้ successful
    รวมถึงทดสอบ point-in-time restore ให้ทำได้จริง
    DBA
  • Install Monitoring Agent บนทุก VM
    Zabbix / PRTG / ระบบที่โรงพยาบาลใช้ — ต้องมี alert สำหรับ disk full, high IOPS, replication lag
    IT Engineer
  • Document baseline metrics ก่อน cutover
    TPS, IOPS per pool, CPU%, RAM%, log write latency, replication lag — เก็บไว้ compare หลัง go-live
    DBA IT
  • UAT กับ Clinical team ก่อน cutover จริง
    ทดสอบ scenario หลัก: OPD registration, IPD admission, dispensing, report generation
    IT Clinical team
